# 標籤核對網頁第一版

手機拍照或相簿上傳 → 中文 OCR 全文掃描 → 對應既有系統標籤、逐行與日期規則核對。

閱讀介面預設大字：辨識文字 20px、主要按鈕 18px（瀏覽器預設字級下）。頁首可切換「大字／特大字」，偏好只保存在目前瀏覽器。手機將逐行訂正操作放在文字下方，差異對照改為上下排列；文字使用 rem，可隨閱讀設定放大。
本專案位於 `C:\build\barcode53_phase1\label_web`，與原有 PyQt 桌面程式分開啟動。

## 已實作

- 標準照片上傳、辨識原文、人工修正與核准。
- 「掃描標籤」以 HTTPS 網頁開啟後鏡頭，按下拍攝後辨識；不支援時可改用手機拍照或選照片。
- 不需要正確照片即可直接掃描。依完全對應的品名、貨號等找出 `db_0801` 的同一款標籤；多款或無法對應時可自行選擇，近似品名僅供建議，不會自動選用。每次核對唯讀取得最新內容，並保留來源版本快照。
- 結果逐行顯示「✓ 相符／✕ 有差異／？待確認／· 僅辨識」，異常置前，同一 OCR 行不重複列出。公司、地址等有錯字、多字或漏字會標示差異；沒有比對依據不判相符。
- 每行 OCR 文字都有對應的檢查或辨識列；日期檢查仍涵蓋合法性、先後及指定本批日期。
- 系統標籤比對容許繁簡、台／臺、全半形、空白及 kg／KG 等格式差異，電話標題可辨識為同一欄位；數字、溫度正負號與字元增刪不會自動修正。保留 OCR 原文、正規化說明與差異證據。
- 可搜尋既有系統標籤，帶入品名、規格、保存條件、產地、公司名稱、地址及電話，人工核准後成為無照片的文字標準。
- 首頁及直接掃描不再使用寫死的四項公司文字；比對文字來自該款系統標籤。既有人工核准照片標準仍保留原有嚴格核對方式，歷史紀錄不改寫。
- 支援右下角未加「公司／地址／電話」前綴的廠商資訊，以文字內容及版面位置定位；候選不確定時要求複核。
- 品名被 OCR 切成同列多個文字框時，依左右位置、間距及基線組合實際辨識文字；保留每個原框與最低信心分數，價格及其他欄位作為邊界，不從標準資料補字。真正缺字、錯字或多字仍保留差異。
- 製造日／有效日格式、先後順序、選填的保存天數與本批製造日。
- 到店日可獨立啟用，檢查日期合法性並與選填的「本批到店日」核對；標準照片的到店日只供建立標準確認，不固定沿用到日後批次。未指定本批到店日不能確認日期是否符合該批作業。
- 系統比對只在辨識分數至少 0.65、候選唯一且內容正規化後相符時顯示勾選；分數並非正確率。極低信心、漏讀或候選不唯一需複核，保留完整照片證據。
- 本批基準日預設台灣當天，可調整檢查歷史標籤。依系統日期格式、位移及有效保存天數核對日期；Barcode.SaveDays 有設定時優先，否則用 BcMst.KeepDays（0 也是有效值）。日期違反日曆、日期先後、來源期望日期或基準年份時會標示，短格式不補出照片未印的年份。
- 檢查紀錄每行可「訂正」照片實際印字，區分 OCR 辨識讀錯、標籤確實印錯及看不清楚。原照片、OCR、分數及判定完整保留，訂正另存版本並重新判定；可逐行撤回。
- 「修正比對標準」可更正同款標籤的品名、文字、保存天數、日期位移及清單已知條碼，先預覽再確認。新版保存在網站獨立資料表，不修改印標程式的版面與主檔；原來源變更後要求重新確認，避免套用過時標準。
- 「重新核對」使用最新來源／日期設定產生新紀錄；有人工訂正時一併沿用，保留訂正人員與來源版本，不覆寫原判定、不重新辨識照片。開啟歷史紀錄會恢復該筆基準日。
- 人工訂正及比對標準採版本衝突檢查；其他人已儲存時阻擋覆寫，保留編輯中的草稿並提供重新載入。
- 比對標準可恢復目前原始來源，或還原同來源的歷史版本；先唯讀取得實際前後差異，再填寫原因並確認。還原會追加新版，原有版本仍保留。
- 原圖框選證據、逐字差異、歷史查詢與獨立人工複核紀錄。
- 展開明細區分「差異對照」與「辨識原文」；〔漏字〕僅是核對標記，不會混入原始辨識文字。
- 標準版本不可覆寫；建立新版時保留舊版和當時檢查快照。
- 照片格式 JPG / PNG / WebP / HEIC，EXIF 方向修正、最大 15 MB / 3,200 萬像素。
- 單一辨識工作執行、最多 12 個待處理工作、重啟時將未完成工作標為失敗。
- 每張照片使用獨立 OCR 程序，完成或逾時後釋放模型記憶體；文字辨識批次為 1，使用 PP-OCRv6 small 偵測＋medium 文字模型。繁忙時上傳會立即提示稍後重試，避免占滿網頁連線。
- Linux 辨識程序會提早釋放大型配置，並監測程序及服務的記憶體預算；超量會停止該張辨識、保留照片並提示重試，不接受部分辨識結果。監測是提早停止機制，並非核心層的獨立記憶體隔離，仍須以實際掃描驗證。
- 每張辨識前及工作結束後回收網頁程序的閒置 heap。只有服務總記憶體超限時，才在回收後用同張照片與同模型自動重試一次，總逾時不延長；程序自身超限或監測不可用仍停止。失敗照片可由「未完成的辨識」直接重新辨識，沿用原日期與比對設定，保留原失敗紀錄並產生新工作。
- Linux 每次辨識前後及模型首次載入後，僅對本服務三個固定 OCR 模型檔提出 `POSIX_FADV_DONTNEED` 快取回收建議；不修改模型或照片，系統不支援或未回收時仍由記憶體保護處理。
- 每次辨識依服務及所有 cgroup 祖先的最小容量決定安全預算：512 MiB 維持子程序 360／預留 96 MiB；2 GiB 使用子程序 1280／預留 256 MiB，服務總用量在 1792 MiB 停止。未知容量不提高預算。`LABELCHECK_OCR_WORKER_MB`／`LABELCHECK_OCR_RESERVE_MB` 只能收緊策略，不能放大超過容量上限。
- 距服務停止門檻 32 MiB 且有至少 16 MiB 閒置檔案快取時，載入途中提早提出定向回收建議；每次最多 8 次、間隔至少 100 ms，回收前後重新檢查門檻，不延長總逾時。依實際 OCR 預算，2 GiB 使用 1600 偵測尺寸改善大照片細字，低容量使用 1280；文字模型、單張執行及批次 1 保持不變。
- 「服務記憶體」可讀取目前用量及清理閒置記憶體。登入及 CSRF 保護、辨識／上傳／排隊中拒絕清理、30 秒操作間隔；不終止工作，不刪資料，不保證使用中的記憶體會下降。每張辨識結束仍自動釋放，不需每次手動清理。
- 無依據的檢查可「建立文字比對標準」：逐行訂正後預覽、填人員及原因並核准，存為 `manual:` 來源及版本。可在標準庫分頁搜尋與選用，同款唯一對應時自動使用。僅人工列入的內容算已核對；原 OCR、照片、判定與印標主檔保留。
- 人工標準的日期只存相對基準日位移；沒有規則就不推定排程，不能把本批固定日期存成永久標準。建立及修改時拒絕互相矛盾的日期位移／保存天數。
- 多張標籤、重複身份欄位及衝突日期會要求裁切單張，所有文字保留而不跨張打勾。空日期標題僅配對附近且中間無阻隔的值；共享／多候選日期需確認。這是歧義保護，不是保證所有未知版面均能自動分割成單張。
- 同一 OCR 行內若有不同且完整的日期標題，會依原文字區段分別核對製造、有效及到店日期；保留原文、座標與行號，不把單一日期借給兩個空標題。同類日期重複仍要求確認。
- 無版面的清單另存 `labelcheck_catalog`，對外代碼使用 `list:`，只核對清單已知品名、原條碼與保存天數。照片有完整且唯一的製造／有效日期時，另核對兩日期間隔是否符合清單天數；缺日期不補值，辨識不確定時需確認。沒有版面與日期位移時，不推造排程或其他印字。
- 同名來源以條碼、規格、產地及其他完整文字消歧；未知欄位不當成不相符。清單的品名、條碼、保存天數與類型完全一致時可共用等價依據，仍保留來源編號。
- 即時相機支援時使用原生靜態照片，備援保留完整影片畫面尺寸；小圖採受限放大以改善細字。v6 字典支援 `※`，但實測仍容易在整句漏讀；遇到單獨此符號差異時提示人工確認，不自動補字。

OCR 並非零錯誤保證。模型信心分數不是經校準的正確率，清楚、完整且無反光的標籤仍需現場樣本驗收。
本版會列出辨識到的全部文字；成分、營養標示等沒有標準的內容僅供閱讀，不能確認無錯字。尚未實作條碼圖形解碼。

人工訂正保存文字框、照片實際印字、錯誤類型、人員、原因及歷次版本，不會自動重訓模型。人工確認只影響所選文字框，保留原始信心分數；標籤印錯仍判異常，看不清楚仍需確認。若要微調模型，須篩選適用標註，不得直接把資料庫標準文字當作照片正解。先保留獨立驗證資料，再離線訓練與評估，通過後才替換部署模型。已確認的分行／版面處理問題優先修正規則並加入回歸測試。

## 本機啟動

### 登入與管理員權限

- 一般密碼 `LABELCHECK_PASSWORD`：掃描、查看檢查紀錄、訂正本筆辨識文字及人工複核。
- 管理碼 `LABELCHECK_ADMIN_PASSWORD`：至少 8 字元、最多 256 字元，必須與一般密碼不同。在同一登入欄輸入管理碼，或登入後按「管理員解鎖」，即可開啟標準庫、建立／修改比對標準與紀錄清理。
- 管理碼未設定、不足長度或與一般密碼相同時，管理功能保持鎖定，一般掃描仍可使用。原有登入工作階段不會自動取得管理員權限。
- 管理權限由後端逐次驗證；隱藏選單不是唯一限制。解鎖會輪替 CSRF，退出管理／登出會撤銷該次管理授權。服務重啟後需重新輸入管理碼解鎖；一般作業仍可沿用有效登入。
- 一般使用者可以選擇已核准照片標準來掃描；只提供選用名稱及版本，不開放標準庫管理資料。
- 本機未設定一般密碼的模式僅允許 loopback，作為本機管理／開發用途；正式與區網使用必須設定一般密碼。

### 訂正、標準與紀錄清理

- 「訂正辨識文字」只更正照片實際印字、重新核對本筆，並保留原 OCR；「建立／修改比對標準」由管理員核准，會影響之後同款標籤的核對。
- 建立人工標準的草稿會帶入已確認為 OCR 誤讀的訂正；標籤印錯、看不清楚及動態日期不能直接變成固定標準。仍須逐字核准並預覽。
- 「清理紀錄」依台灣日期及原始判定篩選，先列出確切筆數與項目，再填確認人及原因移至回收區。每次最多 500 筆，預覽 10 分鐘有效；預覽後新增的紀錄不會一起被清理，有人訂正或複核時需重新預覽。
- 回收區可依批次預覽並還原；照片、OCR、訂正版本、標準與原印標資料均保留。這是整理檢查清單，**不會釋放照片磁碟空間**，本版不提供永久刪除或自動刪除。

選用標準庫可保持空白，直接掃描會對應原系統標籤；未連接資料庫時仍提供文字及日期檢查。也可上傳正確照片建立特定標準；不會把 QA 樣本當作正式標準。

## 共用既有 PostgreSQL

已核對目標為 Render **My Workspace → DB_0801 / db_0801 / Singapore**。

本機要開始將真實建檔資料存入既有資料庫，可先停止本機服務，再執行：

```powershell
.\Start-LabelWeb.ps1 -UseExistingDatabase
```

此參數從父目錄 `config.ini` 在記憶體讀取既有連線，不複製密碼到網頁原始碼。
首次啟動會新增以下獨立資料表，**不會搬移本機 SQLite 已有資料**：

- `labelcheck_images`
- `labelcheck_templates`
- `labelcheck_jobs`
- `labelcheck_inspections`
- `labelcheck_reviews`
- `labelcheck_catalog`
- `labelcheck_corrections`：逐行人工訂正、撤回及重新判定版本。
- `labelcheck_standard_heads`：同款網站比對標準的目前版本。
- `labelcheck_standard_versions`：比對標準修改、還原及修改人員／原因。
- `labelcheck_manual_sources`：人工核准的無版面文字標準、建立依據及來源照片紀錄。
- `labelcheck_history_previews`：限時清理預覽，過期暫存定期於新預覽時回收。
- `labelcheck_history_batches`／`labelcheck_history_tombstones`／`labelcheck_history_audit`：可還原清理批次、回收狀態及操作稽核。

唯讀查詢原有 `barcode53.BcMst / BcDtl`；網站的比對標準修改保存於上述獨立表，不修改列印主檔。匯入時排除不顯示欄位；若來源已變更，核准會要求重新匯入。未連接或遷移正式 DB 的測試不能視為正式資料庫驗證。
只共用資料庫時，照片仍位於執行網頁的主機；搬到 Render 前須一起遷移圖片，不能只切換連線。

- Render 產生登入密碼及 session secret；登入密碼在服務的 Environment 頁面 `LABELCHECK_PASSWORD` 查看，勿放入原始碼或照片。
- 照片（含原始檔）放 `/var/data/labelcheck/images/`；DB_0801 只保存照片索引、標準、OCR 原文與核對紀錄。需同時備份 DB 與持久磁碟。
- OCR 模型以實際記憶體及延遲測量選擇方案；目前採單實例逐張辨識，不能假設高併發時仍有相同效能。
- 尚未提供照片保留期、自動清理、外部備份與大量上傳功能。

單元/API 測試使用注入的辨識結果，涵蓋錯字、門牌數字、日期、低信心、版本快照、覆核、人工訂正、標準編輯、版本衝突、撤回／還原及存取保護。`test_manual_workflows.py` 另外驗證跨流程重新核對與重啟後保存。
`real_ocr_check.py` 使用實際模型辨識合成測試標籤與使用者提供的錯誤照片，產物僅在 `qa/`，不接正式資料庫。
