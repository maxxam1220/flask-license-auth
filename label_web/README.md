# 標籤核對網頁第一版

手機拍照或相簿上傳 → 選擇貼紙範圍與辨識方式 → 對應既有系統標籤、逐行與日期規則核對。

閱讀介面預設大字：辨識文字 20px、主要按鈕 18px（瀏覽器預設字級下）。頁首可切換「大字／特大字」，偏好只保存在目前瀏覽器。手機將逐行訂正操作放在文字下方，差異對照改為上下排列；文字使用 rem，可隨閱讀設定放大。
本專案位於 `C:\build\barcode53_phase1\label_web`，與原有 PyQt 桌面程式分開啟動。

## 已實作

- 檢查結果分區顯示照片、日期、條碼、標籤內容與營養標示。營養成分和單獨標出的熱量只顯示辨識原文。其他欄位有差異時，可展開對照局部照片與標準文字。
- 已有完整標準時，辨識偏差優先「訂正辨識」，不以修改正確標準處理 OCR 錯誤。「更新標準」放在管理操作內；沒有來源時仍可「新建標準」，清單只有部分資料時可「建立完整標準」，皆自動帶入草稿與照片，預覽確認後才儲存。
- 尚無對應標準時，結果頂端先顯示已讀到的製造、有效及到店日期與既有檢查結果，再顯示建立標準和其他內容；沒有日期排程或保存期限依據時明示限制，不把格式通過解讀為全部日期正確。
- 清單及桌面來源可在原代碼上建立網頁完整文字版本，保存原本日期、條碼、保存天數與來源設定，不新增或改寫桌面印標版面。核准後同款核對及標準庫都使用完整版本，歷史紀錄仍保留原標準。照片標準同樣可從本次辨識建立同系列新版，並以新版本重新核對，不會額外呼叫雲端辨識。
- 雲端主要標籤選取規則保留同張貼紙內分散的正文，排除純商標圖案與裝飾性微型字，保留正文中的公司、地址及實際符號。既存不確定且只有缺字方框的片段不自動加入標準草稿；原始辨識仍保留並需看圖確認。這些規則不能保證所有版面都正確，仍應在儲存前對照照片。
- 結果照片與局部文字的放大只讀取已保存圖片，不增加辨識呼叫。人工訂正會立即重新計算本筆判定，重新核對時可沿用；不更改標準、不套用到另一張新照片，也不會自動訓練模型。匯出的改善樣本仍是待審候選。
- 標準照片上傳、辨識原文、人工修正與核准。
- 「掃描標籤」以 HTTPS 網頁開啟後鏡頭，按下拍攝後辨識；不支援時可改用手機拍照或選照片。
- 掃描可選「只看貼紙（自動選取）」或「整張照片」。已設定雲端金鑰且本站允許使用時，網頁預設選用付費雲端辨識；否則預設一般辨識。使用者可自行改用一般辨識，不會因辨識失敗自動在兩者之間切換。
- 不需要正確照片即可直接掃描。依完全對應的品名、貨號等找出 `db_0801` 的同一款標籤；多款或無法對應時可自行選擇，近似品名僅供建議，不會自動選用。每次核對唯讀取得最新內容，並保留來源版本快照。
- 結果逐行顯示「✓ 相符／✕ 有差異／？待確認／· 僅辨識」，異常置前，同一 OCR 行不重複列出。公司、地址等有錯字、多字或漏字會標示差異；沒有比對依據不判相符。
- 每行 OCR 文字都有對應的檢查或辨識列；日期檢查仍涵蓋合法性、先後及指定本批日期。
- 系統標籤比對容許繁簡、台／臺、全半形、空白及 kg／KG 等格式差異，電話標題可辨識為同一欄位；數字、溫度正負號與字元增刪不會自動修正。保留 OCR 原文、正規化說明與差異證據。
- 可搜尋既有系統標籤，帶入品名、規格、保存條件、產地、公司名稱、地址及電話，人工核准後成為無照片的文字標準。
- 首頁及直接掃描不再使用寫死的四項公司文字；比對文字來自該款系統標籤。既有人工核准照片標準仍保留原有嚴格核對方式，歷史紀錄不改寫。
- 支援右下角未加「公司／地址／電話」前綴的廠商資訊，以文字內容及版面位置定位；候選不確定時要求複核。
- 品名被 OCR 切成同列多個文字框時，依左右位置、間距及基線組合實際辨識文字；保留每個原框與最低信心分數，價格及其他欄位作為邊界，不從標準資料補字。真正缺字、錯字或多字仍保留差異。
- 製造日／有效日格式、先後順序、選填的保存天數與本批製造日。
- 到店日可獨立啟用，檢查日期合法性並與選填的「本批到店日」核對；標準照片的到店日只供建立標準確認，不固定沿用到日後批次。未指定本批到店日不能確認日期是否符合該批作業。
- 一般辨識的系統比對只在分數至少 0.65、候選唯一且內容正規化後相符時顯示勾選；分數並非正確率。雲端辨識不提供百分比信心分數，模型標記不確定或疑似錯字時要求複核。極低信心、漏讀或候選不唯一需複核，保留完整照片證據。
- 本批基準日預設台灣當天，可調整檢查歷史標籤。依系統日期格式、位移及有效保存天數核對日期；Barcode.SaveDays 有設定時優先，否則用 BcMst.KeepDays（0 也是有效值）。日期違反日曆、日期先後、來源期望日期或基準年份時會標示，短格式不補出照片未印的年份。
- 檢查紀錄每行可「訂正」照片實際印字，區分 OCR 辨識讀錯、標籤確實印錯及看不清楚。原照片、OCR、分數及判定完整保留，訂正另存版本並重新判定；可逐行撤回。
- 「修正比對標準」可更正同款標籤的品名、文字、保存天數、日期位移及清單已知條碼，先預覽再確認。新版保存在網站獨立資料表，不修改印標程式的版面與主檔；原來源變更後要求重新確認，避免套用過時標準。
- 「重新核對」使用最新來源／日期設定產生新紀錄；有人工訂正時一併沿用，保留訂正人員與來源版本，不覆寫原判定、不重新辨識照片。開啟歷史紀錄會恢復該筆基準日。
- 人工訂正及比對標準採版本衝突檢查；其他人已儲存時阻擋覆寫，保留編輯中的草稿並提供重新載入。
- 比對標準可恢復目前原始來源，或還原同來源的歷史版本；先唯讀取得實際前後差異，再填寫原因並確認。還原會追加新版，原有版本仍保留。
- 原圖框選證據、逐字差異、歷史查詢與獨立人工複核紀錄。
- 展開明細區分「差異對照」與「辨識原文」；〔漏字〕僅是核對標記，不會混入原始辨識文字。
- 標準版本不可覆寫；建立新版時保留舊版和當時檢查快照。
- 照片格式 JPG / PNG / WebP / HEIC，EXIF 方向修正、最大 15 MB / 3,200 萬像素。
- 單一辨識工作執行、最多 12 個待處理工作、重啟時將未完成工作標為失敗。
- 每張照片使用獨立 OCR 程序，完成或逾時後釋放模型記憶體；文字辨識批次為 1，使用 PP-OCRv6 small 偵測＋medium 文字模型。繁忙時上傳會立即提示稍後重試，避免占滿網頁連線。
- Linux 辨識程序會提早釋放大型配置，並監測程序及服務的記憶體預算；超量會停止該張辨識、保留照片並提示重試，不接受部分辨識結果。監測是提早停止機制，並非核心層的獨立記憶體隔離，仍須以實際掃描驗證。
- 每張辨識前及工作結束後回收網頁程序的閒置 heap。一般辨識只有服務總記憶體超限時，才在回收後用同張照片與同模型自動重試一次，總逾時不延長；程序自身超限或監測不可用仍停止。此自動重試不適用於付費雲端辨識。失敗照片可由「未完成的辨識」直接重新辨識，沿用原日期與比對設定，保留原失敗紀錄並產生新工作。
- Linux 每次辨識前後及模型首次載入後，僅對本服務三個固定 OCR 模型檔提出 `POSIX_FADV_DONTNEED` 快取回收建議；不修改模型或照片，系統不支援或未回收時仍由記憶體保護處理。
- 每次辨識依服務及所有 cgroup 祖先的最小容量決定安全預算：512 MiB 維持子程序 360／預留 96 MiB；2 GiB 使用子程序 1280／預留 256 MiB，服務總用量在 1792 MiB 停止。未知容量不提高預算。`LABELCHECK_OCR_WORKER_MB`／`LABELCHECK_OCR_RESERVE_MB` 只能收緊策略，不能放大超過容量上限。
- 距服務停止門檻 32 MiB 且有至少 16 MiB 閒置檔案快取時，載入途中提早提出定向回收建議；每次最多 8 次、間隔至少 100 ms，回收前後重新檢查門檻，不延長總逾時。依實際 OCR 預算，2 GiB 使用 1600 偵測尺寸改善大照片細字，低容量使用 1280；文字模型、單張執行及批次 1 保持不變。
- 「服務記憶體」可讀取目前用量及清理閒置記憶體。登入及 CSRF 保護、辨識／上傳／排隊中拒絕清理、30 秒操作間隔；不終止工作，不刪資料，不保證使用中的記憶體會下降。每張辨識結束仍自動釋放，不需每次手動清理。
- 無依據的檢查可「建立文字比對標準」：逐行訂正後預覽、填人員及原因並核准，存為 `manual:` 來源及版本。可在標準庫分頁搜尋與選用，同款唯一對應時自動使用。僅人工列入的內容算已核對；原 OCR、照片、判定與印標主檔保留。
- 人工標準的日期只存相對基準日位移；沒有規則就不推定排程，不能把本批固定日期存成永久標準。建立及修改時拒絕互相矛盾的日期位移／保存天數。
- 多張標籤、重複身份欄位及衝突日期會要求裁切單張，所有文字保留而不跨張打勾。空日期標題僅配對附近且中間無阻隔的值；共享／多候選日期需確認。這是歧義保護，不是保證所有未知版面均能自動分割成單張。
- 同一 OCR 行內若有不同且完整的日期標題，會依原文字區段分別核對製造、有效及到店日期；保留原文、座標與行號，不把單一日期借給兩個空標題。同類日期重複仍要求確認。
- 無版面的清單另存 `labelcheck_catalog`，對外代碼使用 `list:`，只核對清單已知品名、原條碼與保存天數。照片有完整且唯一的製造／有效日期時，另核對兩日期間隔是否符合清單天數；缺日期不補值，辨識不確定時需確認。沒有版面與日期位移時，不推造排程或其他印字。
- 同名來源以條碼、規格、產地及其他完整文字消歧；未知欄位不當成不相符。清單的品名、條碼、保存天數與類型完全一致時可共用等價依據，仍保留來源編號。
- 即時相機支援時使用原生靜態照片，備援保留完整影片畫面尺寸；小圖採受限放大以改善細字。v6 字典支援 `※`，但實測仍容易在整句漏讀；遇到單獨此符號差異時提示人工確認，不自動補字。

OCR 並非零錯誤保證。模型信心分數不是經校準的正確率，清楚、完整且無反光的標籤仍需現場樣本驗收。
本版會列出辨識到的全部文字；成分、營養標示等沒有標準的內容僅供閱讀，不能確認無錯字。已加入條碼圖形解碼；解碼成功只證明圖形可讀，仍須有同款標準才能確認商品文字與條碼是否正確。

人工訂正保存文字框、照片實際印字、錯誤類型、人員、原因及歷次版本，不會自動重訓模型。人工確認只影響所選文字框，保留原始信心分數；標籤印錯仍判異常，看不清楚仍需確認。若要微調模型，須篩選適用標註，不得直接把資料庫標準文字當作照片正解。先保留獨立驗證資料，再離線訓練與評估，通過後才替換部署模型。已確認的分行／版面處理問題優先修正規則並加入回歸測試。

### 貼紙範圍、雲端辨識與條碼

- 「標籤主要區域（自動選取）」搭配雲端辨識時，會在同一次請求中定位並讀取完整主標籤。一般紙貼保留貼紙內全部文字；透明膜或直接印在包材上的標籤，依版面、間距與字體辨識品名、成分、產地、規格／淨重、日期及條碼所屬的資訊區，並保留同區相鄰的完整營養表，不把條碼白底單獨當成整張標籤。這是跨版型的一般規則，不依固定座標、公司名稱或特定照片決定範圍。
- 雲端自動範圍會排除與主標籤分離的包材品牌、裝飾性大字、廣告及獨立底部包材資訊；不把「條碼下方」一律刪除。同張貼紙內的公司、地址、電話及保存條件，即使在條碼下方仍須保留。多張標籤競爭或無法可靠分出主標籤時，要求手動框選完整標籤後再辨識。自動選區仍須對照原圖確認，不能保證所有反光、透明或傾斜版面都能正確分隔。
- 「標籤主要區域（自動選取）」搭配一般辨識時，仍使用本地影像輪廓選取單張紙貼；找不到明確貼紙時讀取整張照片，透明印刷等無清楚邊界的照片可手動框選。偵測到多張貼紙時要求裁切確認，不把跨張內容判為相符。兩種方式都保留原照片，結果文字框使用原照座標；條碼在選中區域內由本地解碼器處理。
- 「整張照片」讀取完整畫面；若只需一張標籤，拍近或框選單張可減少混讀。自動定位與重複日期等歧義檢查是輔助保護，仍應確認畫面沒有第二張標籤。
- 雲端選項需在服務環境設定 `OPENAI_API_KEY` 才能使用，預設模型為 `gpt-6.1-sol`，可由 `LABELCHECK_CLOUD_MODEL` 指定相容模型。金鑰只從伺服器環境讀取，不填入網頁、不存入標籤資料庫或原始碼。雲端可用時預先選取，使用者仍可改選一般辨識；只有提交雲端辨識工作才會將照片送至 OpenAI Responses API，請求設定 `store: false`。自動選主標籤須傳送整張照片供模型判讀版面；先手動裁切時則只傳送裁切後照片。開啟網頁或讀取預設設定不呼叫模型、不消耗試用次數。
- 每個雲端工作最多發送一次 API 請求，自動選區與文字辨識共用這一次請求，不另呼叫模型定位或重讀；不自動重試、不自動切換模型或充值。辨識逾時、拒絕、回傳不完整或格式不合法時停止本次工作，不用殘缺結果判相符。雲端保留照片實際繁簡字、標點及疑似錯字原文；候選文字僅供人工確認，不拿資料庫標準補寫照片。
- 失敗的雲端照片可明確按「改用一般辨識」，沿用原照片、日期、標準與範圍，不需重新上傳或具備雲端餘額；這是人工選擇，不會自動切換。原失敗紀錄保留，若原工作已有重試，須開啟最新工作再改選，避免同張照片重複執行。
- `LABELCHECK_CLOUD_TRIAL_LIMIT=-1` 開放雲端使用，取消本站累計次數限制；`0` 停用新雲端辨識，正數限制累計次數（預設 `20`，最高 `1000`）。正式服務依使用者要求於 2026-11-17 在 Render Environment 設為 `-1`；此服務設定由 Dashboard/MCP 管理，Blueprint 不覆蓋此鍵。這不是免費或無限 API 額度，實際費用、餘額與速率限制仍由 API 帳戶控制。預留後的失敗、逾時、未知計費工作仍記錄；開放、重啟或重新部署都不清除既有用量。網站不會自動重試、儲值或改用其他模型。
- 相同請求編號與相同照片／設定的網路重送會回放既有工作，不重複建立付費工作；同一失敗工作重送「重試」也回放已建立的直接子工作。使用者對最新失敗工作再次明確重試，或重新提交一筆新辨識，會另占一次試用次數。回傳的 token 用量、模型與耗時另存；未取得用量時標示未知，不能當成免費或零用量。
- 同張標籤上的 HTTP／HTTPS 網址 QR Code 列為履歷查詢碼（QMC001 B 版第 6.1.7 節）。商品條碼獨立與條紋、印字及標準比對。多個商品碼、數字不符或位置無法配對時，結果會提示確認。
- 條碼規則預覽會標出符合 QMC001 B 版餐盒格式的候選。統一第 3.1.4 節用 8 碼店內碼、3 碼有效日年序及時間碼 3；全家第 4.1.3 節用 20、6 碼商品代號、年序末 2 碼及時間碼 24。系統核對完整條碼與照片上讀到的有效日期、時間，再由人員依商品適用通路確認。
- 沒有標準時仍可檢查日期是否合法、前後順序及條碼可讀性等已知規則，但這些勾選只代表該項檢查通過，不能據此宣告所有印字或商品身份正確。
- 條碼區可查看 EAN-13 日期組碼候選：由已知商品前綴、明確日期的 2／3 碼太陽日、本張觀察到的尾碼及檢查碼試算。單張吻合只代表候選成立，不證明真實印製規則，也不推定尾碼代表時刻或保存天數。管理員須開啟預覽、確認日期來源與固定尾碼，再明確確認寫入；一般使用者只能查看推算。
- 核准的條碼公式另存於原標準的網站版本 `web_barcode_rule`，不修改桌面印標設定、標籤全文或照片。以完整日期計算太陽日，保留跨年／閏年及日期本身的判定；核准後須重新核對，舊紀錄不會自動改為相符。推算、預覽、寫入及重新核對都不呼叫雲端辨識。
- 人工文字標準沒有組碼設定時，會依唯一可信的完整 13 碼與日期提供「照片推算候選」，並列出固定前綴、太陽日、尾碼及檢查碼的拆解。唯一的 3 位太陽日候選可先帶入，2 位及其他日期組成仍保留供查看；多個同等候選、明確固定條碼或其他衝突不自動推薦。已有核准規則優先帶入。這些是待確認假設，不等同清單或印標設定已證實。
- 使用者可核對帶入結果、預覽再確認寫入，不必從空白欄位輸入；需修改時可展開手動設定。每個公式須重現本次唯一可信讀值；任何修改都使舊預覽失效。一般人員可從視窗切換管理員後回到同筆重新載入。自動帶入不會儲存、變更判定或使用雲端辨識額度。
- 固定條碼保護依標準的固定條碼欄位或組碼設定判斷，保留的歷史文字行本身不等同固定／日期型的明確宣告。類型尚無來源設定或條紋解碼依據時，核准紀錄保留「接受 EAN13 試算假設」，不記成實物類型已驗證。已有核准公式但本張不符時，不推薦另一公式來取代原規則。
- 日期型條碼保存組碼規則，不將某天完整號碼當成固定比對值；已核准規則涵蓋的獨立條碼數字行改由日期公式核對，原照片和文字仍保留。固定商品條碼仍依固定號碼核對。公式相符與條紋可掃描性分別顯示，沒有成功解碼條紋時仍提醒實際掃碼確認。
- 人工文字標準的 UPC-A 固定商品碼支援 1、5、5、1 位分組印字，例如 `4 00000 79003 9`。標準庫會從已核准的分組文字帶出 `400000790039`。條紋若解碼為 `0400000790039`，會保留該讀值並與 12 碼印字核對。原標準缺少條碼時，可在檢查結果的條碼規則視窗預覽完整號碼，確認後存入該款標準。
- 清單的前後碼、太陽日位數與位置另存為組碼依據，候選依清單約束並顯示檔名、工作表與列號。補充依據保留原有全文標準的身份版本，獨立證據版本防止過期預覽寫入。清單未說明日期來源時不自動套用基準日或有效日，須逐款核准；不把舊欄位「取到期日」直接解成日期位移或日期來源。
- 保存天數僅在標準沒有值、且有可信的製造／有效日期差時預填供確認；已有數值（包含 0 天）保留。這是本張日期間隔的候選，不自動推定日期排程；來源、標準版本或人工訂正變更後，必須重新預覽。

雲端適配器及額度保護有離線模擬測試；部署後仍須以真實 API 與現場照片驗收。不同模型的細字、符號、框線位置、速度與費用須用實際樣本評估，不能承諾每張照片都能正確辨識。

### 裁切重讀與辨識改善資料

- 已完成的檢查可框選照片內單張標籤，再執行真正的 OCR；保留原照片／原始紀錄，新照片及新結果另存。支援觸控、滑鼠與數字範圍調整。裁切至少 100×100 像素且必須在原圖內，仍需保留整張標籤，不能藉裁掉必要欄位判定正確。
- 「重新核對」重用原文字；「重新辨識」重跑模型，兩者分開。重讀沿用原檢查的基準日／製造日／到店日；資料庫標籤重新自動對應，照片標準沿用原快照。人工訂正不複製到新的 OCR。相同圖片、相同模型重跑並不保證改善。
- 重新辨識使用一次性請求編號，網路重送不重複建立工作；改裁切範圍須新編號。仍單工作執行、限制排隊量、沿用原記憶體保護，不改 Render 方案。
- 結果提供實際照片尺寸、文字行數、低分／小字／歧義統計及重試資訊。這些是可觀察數據，不是辨識正確率，沒有警告也不保證沒漏字；缺比對依據與辨識失敗須分開看待。
- 對原圖字框短邊至少 24 像素、包含至少 3 個中文字、原分數低於 .90 的文字，最多 3 行做局部細化筆畫重讀；每塊限制 1024×256 像素。新舊文字不同時保留原文並附候選、要求複核，不以模型分數決定正解。已做整圖旋轉重試者跳過此步，避免座標／方向混用。一般局部讀取錯誤保留主結果並記錄診斷；記憶體保護仍停止整張工作。
- 管理功能提供「辨識改善樣本」摘要與 JSONL 匯出。只收最新有效的 `ocr_misread` 訂正，排除回收區、照片不存在、無效文字框與不同人工答案；同照片同框去重。保留照片相對位置、原 OCR、訂正文字、模型及訂正版本。這是待審候選，不會自動訓練或更換模型，也不直接匯出照片檔。
- 候選需逐張確認框內實際文字、補齊漏框，再按原照片／批次分開訓練與獨立測試資料。離線微調後比較逐字錯誤、日期／條碼完全相符、錯印誤放行、速度與 Linux 記憶體，再決定是否部署。正式 2 GB 網頁不執行訓練。
- 2026-11-13 的離線實圖比較沒有證明 PP-OCRv6 medium-det 或自動選擇單行重讀答案能穩定改善：較大偵測模型增加延遲與記憶體，部分字反而變差。因此維持 small-det＋medium-rec，只將有界重讀作為複核候選，不以標準文字補寫 OCR。

官方微調設定：[PP-OCRv6 medium recognition](https://github.com/PaddlePaddle/PaddleOCR/blob/main/configs/rec/PP-OCRv6/PP-OCRv6_medium_rec.yml)；部署需另行[匯出 ONNX](https://www.paddleocr.ai/latest/en/version3.x/inference_deployment/others/obtaining_onnx_models.html)，不代表現有 ONNX 推論服務會自動學習。

## 標準庫查看、分類與維護

- 標準庫以「已建立標準」為主，人工文字及照片標準統一顯示照片、分類、品名與已有的規格／條碼等辨別資料。「查看內容」直接讀取目前核准版本，不跳轉檢查紀錄，也不需要重新核對或重新辨識。
- 詳細頁顯示參考照片、標籤文字、可辨識的營養分區與日期規則。沒有營養表的標準不要求補填；既有正式標準只展示已保存資料，不拿模型補造文字。建立與版本紀錄放在次要的展開區域。
- 管理員可建立自訂分類，再將標準放入該類。分類只整理標準庫，不改動文字、日期規則或辨識判定；既有未指派資料維持「未分類」，不因品名相同而自動合併。
- 編輯時先預覽差異，再確認儲存新版。人工文字沿用標準版本鏈；照片標準建立同系列的新版本。比對使用最新可用版本，原照片與歷史檢查快照保留。多人編輯、分類或刪除造成版本衝突時，拒絕覆寫並要求重新載入。
- 「刪除」是可還原移除，已刪標準不再用於新掃描；可在「已刪除（可還原）」查看及還原。原始照片、標準版本、檢查紀錄不會永久刪除。已排隊或重新辨識的工作也會檢查標準是否已刪除，不能藉舊快照重新啟用。
- 上方「建立標準標籤」入口移除，待建草稿保留在已建立標準下方的展開區；從檢查結果或草稿確認後建立標準的流程仍可使用。以上查看、編輯、分類與刪除操作均不呼叫雲端辨識。

## 本機啟動

### 登入與管理員權限

- 一般密碼 `LABELCHECK_PASSWORD`：掃描、查看檢查紀錄、訂正本筆辨識文字及人工複核。
- 管理碼 `LABELCHECK_ADMIN_PASSWORD`：至少 8 字元、最多 256 字元，必須與一般密碼不同。在同一登入欄輸入管理碼，或登入後按「管理員解鎖」，即可開啟標準庫、建立／修改比對標準與紀錄清理。
- 管理碼未設定、不足長度或與一般密碼相同時，管理功能保持鎖定，一般掃描仍可使用。原有登入工作階段不會自動取得管理員權限。
- 管理權限由後端逐次驗證；隱藏選單不是唯一限制。解鎖會輪替 CSRF，退出管理／登出會撤銷該次管理授權。服務重啟後需重新輸入管理碼解鎖；一般作業仍可沿用有效登入。
- 一般使用者可以選擇已核准照片標準來掃描；只提供選用名稱及版本，不開放標準庫管理資料。
- 本機未設定一般密碼的模式僅允許 loopback，作為本機管理／開發用途；正式與區網使用必須設定一般密碼。

### 訂正、標準與紀錄清理

- 「訂正辨識文字」只更正照片實際印字、重新核對本筆，並保留原 OCR；「建立／修改比對標準」由管理員核准，會影響之後同款標籤的核對。
- 建立人工標準的草稿會帶入已確認為 OCR 誤讀的訂正；標籤印錯、看不清楚及動態日期不能直接變成固定標準。仍須逐字核准並預覽。
- 建立人工標準時，營養表會依原照片的同列位置，整理成「營養素名稱＋左欄數值＋右欄數值」的完整文字。兩欄相同數值仍保留兩次；缺字不會從標準、鄰列或計算結果補入。
- 新建與人工標準編輯使用「標籤內容」「營養標示」「待確認文字」分區，沒有營養表時不要求補填；日期規則另設。從檢查結果更新既有人工標準時，預設帶入本次可用的辨識草稿，不再先填舊標準。可切回現行標準，兩邊保留尚未儲存的文字；套用新草稿會取代整份固定文字，請確認沒有漏讀。單次日期及沒有固定依據的新／變更條碼不會自動固化，原辨識與日期／條碼邏輯檢查保留。劣質或多標籤辨識不自動帶入。
- 更新人工標準可勾選「將本次照片設為目前標準照片」，預覽後一併保存新版文字與照片關聯；也可只更新照片。標準代碼、分類、原照片與歷史版本保留，同圖不重複附加。訂正或標準版本已變更時拒絕舊預覽；文字及照片任一步驟失敗會整筆回復。從標準庫直接編輯仍以目前核准內容起始，這些操作都不重新呼叫辨識。
- 管理員的標準標籤庫提供「待建立標準」清單，可查看台灣今日或全部尚未建立依據的有效辨識；同一照片只列最新有效紀錄，已建立標準或已附加為參考照者不重複列入。掃描後也可直接開啟標準草稿。草稿使用已保存的辨識文字，不再呼叫雲端；需人工核對、預覽並確認後才寫成正式比對標準。
- 待建立清單可逐筆按「移除草稿」或勾選批次移除，再到「已移除」逐筆或勾選還原。移除只變更這張照片的待建狀態，保留照片、檢查紀錄與已核准標準；同一照片再次核對或辨識不會使草稿重新出現，需明確還原。還原後仍須符合待建條件，已建立標準的照片不會重複列入。同名商品可能有不同規格、配方或日期規則，不會只因品名相同自動合併草稿。
- 新建人工標準的草稿若已混入包材文字，可在照片下按「只保留框選範圍文字」，框住完整主標籤後「預覽保留與排除文字」，確認再「套用到草稿（尚未儲存）」。這項操作只篩選已保存的辨識文字，不重新辨識、不呼叫 API，也不消耗雲端次數；原照片與檢查結果保留。只排除位置可靠且完全在框外的原草稿行；已修改、新增、跨框或無法定位的文字保留並提示確認。可按「撤回這次範圍篩選」恢復，正式儲存前仍須預覽並核准完整文字。此入口適用新建標準草稿，既有正式標準的編輯尚不提供範圍篩選。
- 沒有文字、只有雜訊或整體缺乏可讀內容的紀錄不列入待建立清單；少數字不清楚但仍有可用標籤內容者保留並提示確認。這項篩選依辨識證據判斷，與標籤文字是否印錯分開，原檢查紀錄不因此刪除。
- 點選照片文字或編輯行會定位對應原圖；漏讀內容仍須依照片確認。確認人員、原因、版本衝突保護及歷史版本保留；本批日期不會混入固定文字。
- 營養標示僅供閱讀，包含每份量、每 100 公克／毫升、熱量與各營養素。掃描、重新核對及標準預覽都略過營養換算和營養文字比對。檢查紀錄的異常清單、筆數與判定只計入其他檢查項目。
- 同款標準可以關聯多張參考照片。已有相同內容的標準時，可選「附加到」；已有核對來源的檢查可用「附加這張參考照」，確認同款內容後保存人員、原因及來源版本。建立人工標準後也會嘗試附加本張參考照；若附加失敗，文字標準仍已保存，可用「補掛這張參考照」完成關聯。
- 附加照片不改寫標準文字、日期規則或原始 OCR，也不會自動訓練模型或以照片相似度判定正確。標準更新後，較早版本的參考照會提示重新核對；關聯管理限管理員使用。

## 驗證

完整日期可以帶時間、數字或符號附記，例如 `2026.11.21 24時`、`2026.11.21 ⑤`。24 時整是印刷當日的截止時間，仍以印刷日期計算年序與保存天數。紀錄保留原文，核對時仍檢查日曆及明示時刻。單行「包裝日期」在日期區顯示格式與已執行的年份檢查。

連續掃描預設每張重新自動對應。查看檢查紀錄、重新核對或自動找到來源，都不會將該來源固定給下一張；需在拍攝區明確勾選「固定使用此標準」才會持續沿用。第一次主動選擇的來源只套用下一張，送出後回到自動；網路重送與失敗重試仍保留原請求。

指定標準與照片的可靠完整品名指向不同已知商品時，顯示來源衝突並暫停套用該標準，可用原文字自動重新核對，無需再次雲端辨識。一般錯字仍依選定標準檢查。同名款不以共同公司、地址、電話或保存條件單獨選定；條碼格式空白只在來源明確是 EAN/UPC 時處理，Code128 字面資料不變。無法唯一判斷時仍需確認，不能保證自動對應永遠正確。
